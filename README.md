## 📚 <span id="git-컨벤션">git 컨벤션</span>
### 브랜치 전략
**Git Flow 방식: main ← dev ← feat/닉네임/이슈번호**
- main: 배포 브랜치
- dev: 개발 브랜치
- feat/닉네임/이슈 번호

### 브랜치 명명 규칙 
**브랜치 형식: 브랜치종류/닉네임/이슈번호**
- 브랜치 종류: feat, refactor, bug  등등…


### 커밋 메세지 규칙 
**Gitmoji 사용**
  
| 이모지 | 타입          | 설명               |
|--------|---------------|--------------------|
| ✨     | Feat          | 새로운 기능 추가    |
| 🐛     | Bug           | 오류 수정          |
| 🔨     | Fix           | 코드 수정          |
| ♻️     | Refactor      | 코드 리팩토링      |
| 🚑     | Hotfix         | 급한 오류 수정 |
| 👷     | Ci         | ci/cd 파이프라인 구축        |

### 커밋 메세지 형식 
```
:이모지: [Feat/Bug/Refactor] Title

ex) ✨[Feat] API 구현
```
